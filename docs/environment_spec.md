# 环境建模与接口说明

## 1. 数组布局

环境使用 `team, agent, feature` 布局：

- `observation`: `(2, N, observation_dim)`；
- `action`: `(2, N, 2)`；
- `reward`: `(2, N)`；
- `active_masks`: `(2, N)`；
- `global_state(team)`: `(state_dim,)`。

两维连续动作依次是归一化加速度和归一化角速度，范围均为 `[-1, 1]`。死亡智能体动作被屏蔽为零。

## 2. 运动学

每个物理子步执行：

```text
v'   = clip(v + a * dt, v_min, v_max)
psi' = wrap(psi + omega * dt)
x'   = x + v' * cos(psi') * dt
y'   = y + v' * sin(psi') * dt
```

每个策略动作持续 `decision_dt / physics_dt` 个物理子步。

## 3. 观测

自身特征包括：

- 阵营视角归一化位置；
- 归一化速度；
- 航向角正弦和余弦；
- 弹药、锁定进度；
- X/Y 边界余量；
- 剩余时间、存活标志和越界计时。

实体槽位首先排列其他友机，再排列敌机。每个实体包含机体系相对位置、相对速度、距离、相对航向、方位角、存活、可见、阵营、可攻击和威胁标志。友机信息视为通过数据链共享；敌机只有进入本机雷达扇区后才公开运动状态。

Critic 状态始终以当前阵营为己方，对蓝方进行 180 度坐标变换，使同一网络可用于红蓝两侧。

## 4. 作战逻辑

目标需同时满足：

1. 距离小于武器射程；
2. 位于攻击者前向武器扇区；
3. 攻击者位于目标尾后危险扇区。

持续满足条件达到 `lock_seconds` 后确定性命中，并消耗一发弹药。锁定中断时进度按 `lock_decay_rate` 衰减。多个攻击者在同一物理子步命中相同目标时只记录一次击毁。

## 5. 奖励

阵营事件奖励由击毁、损失、胜负、边界、碰撞和微小时间代价组成。密集塑形采用势函数差分：

```text
r_shape = scale * (gamma * Phi(s_next) - Phi(s))
```

`Phi` 只衡量尾后攻击优势和被威胁程度。差分形式减少反复接近/远离刷取绝对距离奖励的风险。

智能体最终奖励为团队事件奖励和本地击毁/损失事件的加权组合。训练器使用阵营平均奖励计算团队 Critic 的 GAE。

## 6. 终局

任意一方全灭时立即结束。达到最大时间时只比较双方存活数量，存活数相同即为平局。中心区域和剩余弹药不参与胜负裁决。

评估阶段记录双方击毁数、击毁差、发生击毁的回合比例和首次击毁时间。这些指标用于区分“真正发生空战的胜负”和无交战平局，不参与训练奖励。

## 7. MAPPO

同一阵营所有同构智能体共享 Actor。Actor 和 Critic 均包含 GRU，完整回合按时间顺序重新展开，采用 GAE、PPO clipped policy loss、clipped value loss、熵奖励和梯度裁剪。死亡掩码不会让无效动作进入策略损失。

训练前期使用规则追击对手，之后从有限历史快照池采样敌方。快照只冻结 Actor；正在学习的 Actor/Critic 仍按每回合数据更新。

## 8. 并行采样

训练使用 `multiprocessing` 的 spawn 子进程。每个工作进程独立创建环境、维护动力学状态并使用独立种子。主进程先为所有活动环境计算动作，再同时下发，最后统一接收各进程结果。一个采样批次内的网络参数保持不变；全部并行回合结束后，多条轨迹共同归一化优势并合并计算一次 PPO 更新。这与单进程依次运行多个环境不同。
